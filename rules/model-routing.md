# 모델 라우팅 · 위임 규칙 (전역)

최종 갱신 2026-08-20. 이 문서는 Claude·Codex 양쪽 CLI에 동일하게 배포된다.
모델 목록은 낡을 수 있으니 쓰기 전 `list_models`로 확인한다.

## 0. 역할

- **오케스트레이터** — 기획·분해·판정·승인. 어떤 모델이든 될 수 있다.
- **서브에이전트** — 실행. 기본은 코덱스.
- **클로드는 선택 사항.** 없으면 §3의 코덱스 단독 폴백을 쓴다.

오케스트레이터의 토큰이 희소자원이면 토큰이 많이 드는 일은 전부 서브에이전트로 넘긴다.

- 오케스트레이터가 **클로드**일 때: 클로드 서브에이전트를 띄우지 않는다. 판단이 필요하면 직접 한다.
  서브에이전트로 띄우면 희소자원을 쓰면서 컨텍스트까지 잃는다.
  예외는 오케스트레이터 컨텍스트가 고갈 직전인데 대용량 판정이 남았을 때뿐.
- 오케스트레이터가 **코덱스**일 때: §3의 클로드 행에 걸리면 클로드 서브에이전트를 띄운다.
  클로드를 쓸 수 없으면 폴백으로 간다.

## 1. 선언·승인 (다른 모든 규칙에 우선)

서브에이전트·어드바이저·위원회·병렬 워커를 띄우기 전에 **먼저 사용자에게 말한다**:

- 오케스트레이션 플랫폼/프로바이더
- 정확한 모델과 추론강도 (프로파일을 쓰면 그것이 해석된 모델·설정)
- 구체적 작업·범위·예상 산출물
- 읽기 전용인지, 파일 수정 권한이 있는지
- 왜 위임이 필요한지

그리고 **매 실행마다 개별 승인을 기다린다.**
"필요하면 서브에이전트 써라" 같은 포괄 허가는 이 요구를 면제하지 않는다.

- 승인된 프로바이더·모델·추론강도·범위·쓰기권한을 바꾸려면 다시 승인받는다.
- 사용자가 특정 프로바이더나 모델을 금지하면 메인·서브 어디에도 쓰지 않는다.
- 승인 대기 중에는 띄우지 않는다. 승인을 우회하지 않는 직접 작업만 계속한다.
- 위임이 승인되면 Paseo를 우선한다.

## 2. 라우팅

**원리 1 — 모델 격차는 작업 난이도에 비례한다.**
일상 코딩(SWE-Bench Pro)에서 Sol-Luna 격차는 1.9%p인데 익스플로잇에서는 40.3%p다.
난도가 낮으면 Luna가 25배 싼 값에 거의 같은 일을 한다.

**원리 2 — 무엇을 산출하느냐로 위험이 갈린다.**
읽기·조사는 틀려도 오케스트레이터가 거른다. 코드 생성(§4)과 판정(§5)은 위험하다.

| 어떤 일인가 | 설정 |
|---|---|
| 폴링·다운로드·파일 찾기·단순 툴 호출 | `luna` low |
| **조사·리서치·코드 읽기·1차 탐색** (기본값) | `luna` high |
| 대량 기계적 변환 (같은 패턴 N개 파일) | `luna` high **N기 병렬** |
| 일상 코드 생성 (되돌릴 수 있음) | `luna` high → **오케스트레이터 검수 필수** (§4) |
| 입력 200K 초과 장문 | `terra` high~max |
| 디버깅·근본원인 (독립 가설 여럿) | 가설별 `luna` high 팬아웃 → `sol` xhigh로 수렴 |
| 보안·암호·동시성·결제·인증 | `sol` xhigh + §5 |
| 되돌릴 수 없는 것 (프로덕션·스키마·외부 발송) | `sol` xhigh + 사전 승인 |
| 분해 불가능한 단일 최난도 | `sol` max |
| **프로덕션 테스트 작성** | §3 |

- `luna` medium→high가 전 구간 가성비 최고 (AA +8점에 +$0.01). 기본값인 이유.
- `luna`는 256K 이상에서 MRCR 41.3%로 붕괴한다 (Sol 91.5 / Terra 89.6).
  512K~1M도 동일하게 41.3% — 경사가 아니라 절벽이다. 장문에 쓰지 않는다.
- **`sol` low 금지** — `luna` max(52점/$0.05)가 `sol` low(51점/$0.23)보다 싸고 강하다.
- `sol` high는 근거가 엇갈린다. AA 종합지수로는 medium→high가 +1점에 비용 +49%지만,
  GPT-5.5 실측에서는 high가 품질/비용 최적점(0.1544, xhigh 0.0905)이었다.
  `sol`을 쓸 이유가 있으면 xhigh로 가고, 애매하면 `luna` high로 내린다.
- **`ultra` 금지.** §6.

## 3. 클로드를 쓸 수 있을 때와 없을 때

클로드가 코덱스보다 확실히 나은 건 아래 셋뿐이다. 나머지는 코덱스가 같거나 낫다.

| 상황 | 클로드 가용 | **코덱스 단독 폴백** |
|---|---|---|
| 프로덕션 테스트 작성 | Opus 5. Scale 독립평가 `62.22±5.58` vs Sol `45.90±6.00`, 신뢰구간 분리 | `sol` xhigh + **작성한 테스트를 실제로 실행해 검증한다.** 모델 품질을 실행 결과로 대체 |
| 고위험 보안 2차 검토 | 다른 패밀리로 교차 (§5) | **정적분석 도구 병행 필수** (Semgrep·CodeQL 등). 코덱스가 못 보는 XSS·SQLi·IDOR를 도구가 맡는다 |
| 단일 요청 입력 272K 초과 | Opus 5. 500K+20K 기준 $3.00 vs Sol $5.90 | **272K 아래로 샤딩한다.** 한 요청에 다 넣지 않는다 |

코덱스 단독 운용은 보안 블라인드스팟을 감수하는 선택이다.
도구로 메우되, 메워지지 않는 부분이 남는다는 걸 알고 쓴다.

클로드 우위 근거가 **없는** 것 (통념 기각):

- 심층 리서치 — 동일 하네스에선 격차 4.7%p, 네이티브 도구는 Sol 역전(69.0 vs 67.0), BrowseComp도 Sol 90.4 우세
- 초장문 *품질* — 근거 약함. 유리한 건 비용뿐
- 지시 준수·안전성 — IFBench Sol 72.7 > Fable 63.5
- 대규모 리팩터 — SWE-bench Pro 79.2 vs 64.6은 벤더 각자 측정이고 리팩터 전용 벤치마크가 아니다

도구 제약(모델 우열과 무관): 힉스필드·미디어 생성 MCP는 클로드 쪽에만 붙어 있다.

## 4. 코덱스가 쓴 코드는 검수 없이 머지 금지

GPT-5.5 → Sol 변화 (SonarSource, Java 4,444과제):

| 항목 | GPT-5.5 | Sol | 변화 |
|---|---:|---:|---:|
| 기능 테스트 통과율 | 78.66% | 81.99% | +3.33%p |
| Critical 취약점/mLOC | 20 | 125 | **6.25배** |
| 암호화 설정 오류/mLOC | 17 | 67 | 3.94배 |
| 동시성·스레딩 버그/mLOC | 165 | 352 | 2.13배 |

**더 잘 작동하면서 더 위험해졌다.** 통과율이 올라 눈에 안 띄니 오히려 더 위험하다.
테스트 통과를 신뢰 신호로 쓰지 않는다.

Terra도 유사하다(취약점 203/mLOC, 암호화 4.47배). Luna는 이 평가에서 제외되어 **데이터 없음**.
정확히: Sonar 등급은 blocker > critical이고 blocker는 18→9로 감소했다.
"최고 심각도가 6.25배"라고 쓰면 부정확하다.

## 5. 보안 리뷰 프로토콜

- **단일 모델 1패스를 확정 판정으로 쓰지 않는다.** 실측 정밀도 14~18%(오탐 82~86%),
  같은 프롬프트를 3회 실행하면 발견 수가 3/6/11로 변동한다.
- **코덱스는 웹 취약점에서 구조적으로 실패한다**: XSS 0/28, SQLi 0/5, IDOR 0/5.
  반대로 path traversal 8/17, SSRF 8/23은 상대 강세다. 클로드는 IDOR 13/59, XSS 12/74로 정반대.
  → 웹 앱 보안은 클로드 교차 또는 정적분석 도구가 **반드시** 붙는다 (§3).
- 순서: `luna` high 광범위 스캔 → `sol` xhigh 재현·증거 수집 → 오케스트레이터 판정.
  보안에서 `luna` 단독 결론은 금지 (ExploitBench 33.2%).
- 교차검증도 정적분석·테스트·실제 재현을 대체하지 못한다.

## 6. ultra 금지

근거는 "ultra가 나쁘다"가 아니라 **안전장치를 Paseo에서 걸 수 없다**는 것이다.

- `spawn_agent`의 `fork_turns` 기본값이 `all` = 부모 전체 히스토리 복제. 모델·강도도 부모 상속.
- MultiAgent V2가 요청 없이 다단계 자손을 생성하고, V1의 `agents.max_depth`가 V2에 미적용.
- 서브에이전트 25개에서 429 재현. **워커 N기 × ultra = 동시 요청이 곱셈으로 증가.**
- 실측: 동일 작업에서 ultra가 주간 한도 90~110% 소모, 명시적 6-agent `sol` medium은 40%로 유사 결과.
- Paseo가 `fork_turns`·depth·자식 모델을 노출하면 재검토한다.

반례(기록용): 상위에서 미리 쪼갤 수 없던 leaf 작업에서는 ultra가 실제로 이긴다
(SEC-Bench Pro 71.2→74.3, Terminal-Bench 88.8→91.9).
우리 구조에서는 그때 오케스트레이터에 보고하고 워커를 더 띄운다 — 왕복 한 번 값을 내고 통제를 산다.

## 7. 비용

- **입력 272K 초과 시 요청 전체가 재가격된다** (입력 2배, 출력 1.5배). 273K는 272K의 2배다.
  넘기지 말고 쪼갠다.
- 크레딧 단가 **Sol : Terra : Luna = 25 : 10 : 1**
  (1M 토큰당 입력 125/50/5, 출력 750/300/30 credits. 1 credit = $0.04)
- 강도 배수는 공식 고정표가 없다. 실측(GPT-5.5): low 1.00 / medium 1.18 / high 1.69 / xhigh 3.69배.
- 레이트리밋을 태우는 것: 긴 스레드, 큰 AGENTS.md, MCP 주입 컨텍스트, 반복 압축,
  fast mode, 병렬 하위 에이전트.
- Free/Go는 Sol 사용 불가. 공식 페이지끼리 한도 수치가 불일치 —
  계정의 Codex Usage Dashboard가 최종 기준.
