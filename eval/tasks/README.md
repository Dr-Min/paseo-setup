# 과제 원문

아래 프롬프트를 **양쪽 모델에 글자 하나 다르지 않게** 보낸다.
`<OUT>` 만 각 모델의 출력 경로로 바꾼다.

설계 원칙:

- **구현만 시키고 테스트는 채점자가 쓴다.** 자기가 만든 테스트로 자기를 채점하면 의미가 없다.
- **구현 방법은 지정하지 않는다.** 시그니처와 명세만 준다.
  2026-08-20 회차에서 Sol 은 정규식으로, Luna 는 문자 단위 검사로 풀었고 둘 다 만점이었다.
- 과제 3개는 일상 코딩이면서 각각 **엣지케이스 / 동시성 / 보안**을 하나씩 건드리게 골랐다.

## T1 — semver 비교 (엣지케이스)

````
코드 작성 과제다. 결과물은 `<OUT>/solution.py` 파일 하나뿐이다.

구현할 것:

```python
def compare(a: str, b: str) -> int:
    """SemVer 2.0.0 버전 문자열 두 개를 비교한다.
    a < b 이면 -1, a == b 이면 0, a > b 이면 1을 반환한다.
    유효하지 않은 버전 문자열이면 ValueError를 발생시킨다.
    """
```

SemVer 2.0.0 명세를 정확히 따라라.

제약: Python 3 표준 라이브러리만 사용. 외부 패키지 금지. 테스트 코드는 작성하지 마라 — 구현만 제출한다. 다른 파일을 만들지 마라.

완료하면 "완료"라고만 답해라. 설명 불필요.
````

## 알려진 결함

프롬프트에 **파이썬 버전을 안 적었다.** 2026-08-20 회차에서 Luna 가 3.10+ 문법
(`list[str] | None`)을 써서 3.9 환경에서 임포트가 실패했다.

이 결함은 **일부러 고치지 않고 둔다.** 회차 간 비교가 성립하려면 프롬프트가 같아야 한다.
버전을 명시한 프롬프트로 다시 재보고 싶으면 새 과제 세트로 분리해라.
