# eval — 라우팅 규칙 검증

**설치와 무관하다.** `install.sh` 는 이 디렉터리를 건드리지 않는다.
`rules/model-routing.md` 의 모델 선택 근거를 실측으로 확인·재확인하기 위한 것이다.

규칙에 "일상 코드 생성은 `luna` max" 라고 써놓고 근거가 커밋 메시지에만 있으면
나중에 검증할 수 없다. 그래서 채점기와 과제 원문을 규칙과 **같은 저장소·같은 히스토리**에 둔다.

## 구성

```
eval/
  grade.py            채점기. 구현을 보기 전에 작성됐다
  tasks/README.md     양쪽 모델에 보낸 프롬프트 원문
  runs/<날짜>/<과제>/<모델>/solution.py
```

## 돌리는 법

```bash
python3 eval/grade.py                      # runs/ 의 가장 최근 회차
python3 eval/grade.py eval/runs/2026-08-20 # 특정 회차
```

모델 디렉터리 이름은 자유다. `runs/<날짜>/t1/<이름>/solution.py` 구조만 맞으면
2개든 5개든 자동으로 찾아서 나란히 채점한다.

## 재측정 규칙

1. `tasks/README.md` 의 프롬프트를 **글자 하나 바꾸지 말고** 보낸다.
2. `grade.py` 를 **고치지 마라.** 고치면 이전 회차와 비교가 성립하지 않는다.
   과제를 늘리고 싶으면 t4 를 추가하되 t1~t3 채점 로직은 그대로 둔다.
3. 새 회차는 `runs/<날짜>/` 에 새로 만든다. 기존 회차를 덮어쓰지 않는다.

## 2026-08-20 회차

`luna` max 대 `sol` xhigh. Sol 쪽을 max 가 아니라 xhigh 로 잡은 이유는
라우팅 표가 일상 코드 생성에 sol max 를 배정하는 경우가 없어서다 — 실제 대안과 비교해야 한다.

| 과제 | luna max | sol xhigh |
|---|---|---|
| T1 semver (18) | 임포트 실패 → 문법 우회 시 18/18 | 18/18 |
| T2 토큰버킷 (7) | 7/7 | 7/7 |
| T3 안전경로 (11) | 10/11 | 11/11 |

**로직 정답률은 35/36 대 36/36 으로 사실상 같았다.** 격차는 로직이 아니라
요구사항에 안 적힌 주변에서 났다.

1. **런타임 호환성** — Luna 가 3.10+ 문법을 써서 py3.9 에서 임포트 실패.
   로직은 완벽했다. 프롬프트에 버전을 안 적은 쪽 책임도 있다.
2. **명시적 방어** — Sol 은 `safe_join` 에 널바이트 검사를 넣었고 Luna 는 안 넣었다.
   다만 파이썬 `open()` 이 널바이트를 자체 거부하므로 실제 악용 가능성은 희박하다.
   방어를 넣고 안 넣고의 **경향** 차이지 취약점을 막은 사건이 아니다.

Luna 가 유일하게 의미 있게 진 항목이 보안 과제였고, 라우팅 표는 이미 보안을 `sol` 로 보낸다.

**표본은 n=3 이다.** 방향을 본 것이지 크기를 잰 게 아니다. 이 수치로
"Luna 가 Sol 의 97%" 같은 일반화를 하면 안 된다.
